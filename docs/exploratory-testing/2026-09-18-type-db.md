## Journeys exercised

### 1. Coverage-guided property-based testing (CGPT) and round-trip fidelity

Goal: generate 10,000 randomized test cases across normal doubles, subnormals (`4.94e-324`), powers of two, edge values (`PHP_FLOAT_MIN`, `PHP_FLOAT_MAX`, `PHP_FLOAT_EPSILON`, `0.0`), multi-byte UTF-8 strings, large signed integers, and nulls, verifying lossless round-tripping through `quick_query()` and SQLite storage classes.

Result: passed. All tested values roundtripped with bit-identical fidelity through `quick_query()`. Mixed types across rows in dynamic SQLite columns correctly resolved row-specific storage classes without coercive decay.

### 2. Metamorphic SQL expression and column name invariance

Goal: verify metamorphic invariants across SQL queries and expressions:
1. Column name invariance: for any SQL expression with bound parameters, result column keys must not change when parameter types switch between `SqlFloat` and `SqlInteger`.
2. Alias invariance: aliased expressions must preserve explicit alias names regardless of internal parameter casts.
3. Positional vs named binding equivalence.

Result: passed under default connection configuration (`PDO::CASE_NATURAL`).

### 3. PDO Driver Attribute Configurations (`PDO::ATTR_CASE`)

Goal: evaluate TypeDb against custom driver configurations commonly used by frameworks and applications, specifically column case normalization via `PDO::ATTR_CASE` (`PDO::CASE_LOWER` and `PDO::CASE_UPPER`).

Result: defect found ([#48](https://github.com/jonbaldie/type-db/issues/48)).
- `sqlite_result_column_name()` restores rewritten float parameter column names using `str_replace()`, which performs strict case-sensitive matching against uppercase SQL keywords (`CAST`, `AS`, `REAL`) and lowercase internal marker comments (`/* type-db:float-rewrite-<N> */`).
- When `PDO::ATTR_CASE` is set to `PDO::CASE_LOWER` or `PDO::CASE_UPPER`, PDO normalizes all column names to lowercase or uppercase before `quick_query()` inspects them.
- As a consequence:
  1. `str_replace()` fails to match the normalized column names under both `PDO::CASE_LOWER` (due to lowercase `cast(...) as real`) and `PDO::CASE_UPPER` (due to uppercase `/* TYPE-DB:FLOAT-REWRITE-... */`).
  2. Unaliased float queries leak raw internal rewrite expressions and comment markers into result keys (e.g. `'cast(? as real) /* type-db:float-rewrite-1 */'`).
  3. Row shape becomes non-deterministic based on parameter type: `select ?` bound to an integer yields key `'?'`, while bound to a float it yields `'cast(? as real) /* type-db:float-rewrite-1 */'`.
  4. Duplicate column validation in `statement_duplicate_column_names()` is completely bypassed for unaliased float columns (e.g. `select ?, ?` with floats returns two columns with differing rewrite IDs rather than throwing the expected `RuntimeException`).
