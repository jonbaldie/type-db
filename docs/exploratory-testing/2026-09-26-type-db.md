# Exploratory testing report: type-db

Date: 2026-09-26

Repository: `main` at `45aaf3a` (`Merge pull request #64 from jonbaldie/release/v0.11.0`)

## Interface and environment

This pass evaluated the public interface of TypeDb (`TypeDb\Connection`, `quick_query()`, `TypeDb\RowHydrator`, `to_sql()`, `from_sql()`, and `SqlValue` implementations) across three user-critical journeys:

1. **Result Hydration, Schema Affinities, and Result Topology**: evaluating the new `RowHydrator` component across diverse SQL statement topologies (DDL, DML, empty SELECT sets, views, recursive CTEs, window functions, and aggregates) and column affinities (`INT`, `BIGINT`, `REAL`, `FLOAT`, `DOUBLE`, `NUMERIC`, `DECIMAL`, `BOOLEAN`, `DATETIME`, `VARCHAR`, `TEXT`, `BLOB`, `ANY`).
2. **Public Extension Surface & Custom `SqlValue` Implementations**: evaluating polymorphic operational dispatch on duck-typed custom `SqlValue` implementations (`unwrap()`, `toPdoParameter()`, `pdoParameterType()`), boundary float round-tripping, large 64-bit integer preservation, subnormal float precision, complex multi-byte/astral emoji strings, binary payloads, and invalid implementation/`NAN` error boundaries.
3. **Driver Configuration Statefulness & Metamorphic Invariance**: evaluating behavior under driver configurations (`PDO::ATTR_CASE`, `PDO::ATTR_STRINGIFY_FETCHES`, `PDO::ATTR_ERRMODE`), and testing metamorphic invariance across positional parameter forms (`?`, `?NNN`), named parameters (`:param`, `:ns::param`, `:arr(idx)`), aliased vs unaliased expressions, and SQLite JSON operators (`->`, `->>`).

Environment:
- PHP 8.5.9
- SQLite 3.53.4 via `pdo_sqlite`
- Composer dependencies installed from lock file
- Working tree clean before the pass

## Journeys exercised

### 1. Result Hydration, Schema Affinities, and Result Topology

Goal: verify that `RowHydrator` (introduced in v0.11.0 via #58 / #63) and `quick_query()` accurately hydrate query results across all SQLite statement types, affinities, and schema topologies.

Areas tested:
- **DDL and DML commands**: verified that `CREATE TABLE` and `INSERT` commands execute cleanly and return empty lists (`[]`) without attempting hydration on 0-column result sets.
- **Empty query result sets**: verified that `SELECT ... WHERE 0` returns an empty list while validating metadata up front.
- **Polymorphic column storage classes**: verified that dynamic affinity columns (`CREATE TABLE t (v ANY)`) preserve distinct per-row SQLite storage classes (`SqlInteger`, `SqlFloat`, `SqlString`, `SqlNull`) without coercive decay.
- **Schema column affinities**: verified mapping fidelity across 12 declared affinities (`INTEGER`, `BIGINT`, `REAL`, `FLOAT`, `DOUBLE PRECISION`, `NUMERIC`, `DECIMAL(10,2)`, `BOOLEAN`, `DATETIME`, `VARCHAR(255)`, `TEXT`, `BLOB`), ensuring integer preservation, exact float decoding, and lossless binary string extraction.
- **Complex query topologies**: verified clean hydration through SQLite views, recursive common table expressions (`WITH RECURSIVE seq ...`), window functions (`row_number() OVER (...)`, `count(*) OVER ()`), and aggregate functions (`count(*)`, `max(id)`).
- **Duplicate column detection**: verified that unaliased duplicate column names throw the expected `RuntimeException: Failed to interpret query [HY000/unknown]: Duplicate column names in result set: ...`.
- **Exhausted statement and re-fetch behavior**: verified that invoking `fetchAll()` multiple times on an exhausted cursor returns an empty array cleanly without throwing.

Result: passed (all 7 steps verified).

### 2. Public Extension Surface & Custom `SqlValue` Implementations

Goal: verify the extensibility of `SqlValue` implementations and operational dispatch via `unwrap()`, `toPdoParameter()`, and `pdoParameterType()` introduced in v0.10.0 (#59 / #60).

Areas tested:
- **Custom duck-typed `SqlValue` implementations**: created custom userland classes implementing `SqlValue` with polymorphic operations (`unwrap()`, `toPdoParameter()`, `pdoParameterType()`) and bound them into queries. Verified that `sqlite_float_parameter_sql()`, `bind_sql_value()`, and `sql_value_parameter_type()` dispatch cleanly through the custom methods.
- **Boundary float conversions**: verified bit-identical round-tripping through `to_sql()`, `from_sql()`, and query execution for `0.0`, `-0.0`, `1.0`, `-1.0`, `3.141592653589793`, `PHP_FLOAT_MIN`, `PHP_FLOAT_MAX`, `PHP_FLOAT_EPSILON`, `1.5e-300`, `1.5e300`, `INF`, and `-INF`.
- **NAN rejection**: verified that binding a `SqlFloat(NAN)` throws `InvalidArgumentException: NAN cannot be represented by SQLite.` before query preparation.
- **Incomplete / invalid implementations**: verified that passing custom `SqlValue` implementations lacking required operations to `from_sql()`, `bind_sql_value()`, or `sql_value_parameter_type()` throws `InvalidArgumentException: Unsupported SqlValue implementation: ...`.
- **Large 64-bit integers**: verified full 64-bit integer range preservation (`PHP_INT_MIN` and `PHP_INT_MAX`) without conversion to floats or truncation.
- **Subnormal floats**: verified that subnormal floats (e.g. `4.9406564584125E-324`) round-trip with bit-identical fidelity.
- **Complex multi-byte strings, astral characters, and binary data**: verified that UTF-8 astral plane characters (e.g. `𠜎`, `𠜱`), emojis (`🚀`, `🌟`), accented strings (`café`, `naïve`), binary NUL bytes (`\0`), and raw binary bytes (`random_bytes(256)`) preserve data losslessly.

Result: passed (all 7 steps verified).

### 3. Driver Configuration Statefulness & Metamorphic Invariance

Goal: evaluate TypeDb against custom driver configurations and verify metamorphic query invariants across parameter binding formats and SQL expressions.

Areas tested:
- **`PDO::ATTR_CASE` normalization**: verified that column names and unaliased named float parameter column keys respect `PDO::CASE_LOWER` and `PDO::CASE_UPPER` normalization without leaking internal float rewrite expressions.
- **`PDO::ATTR_STRINGIFY_FETCHES`**: verified that under stringified fetches, numbers, strings, nulls, and stringified infinities (`9e999` / `-9e999`) resolve to their respective `SqlInteger`, `SqlFloat`, `SqlString`, and `SqlNull` representations.
- **`PDO::ATTR_ERRMODE` deterministic translation**: verified that when `PDO::ERRMODE_SILENT` is active, query preparation errors deterministically throw `RuntimeException: Failed to prepare query [HY000/1]: near "...": syntax error. SQL: ...` rather than silently returning empty results.
- **Parameter form metamorphic invariance**: verified that positional anonymous (`?`), positional numbered (`?1`), named (`:param`), namespaced named (`:ns::param`), and array-indexed named (`:arr(idx)`) parameter placeholders all yield identical evaluated results.
- **Alias and unaliased expression name invariance**: verified that expressions such as `abs(?)` retain identical column keys (`abs(?)`) regardless of whether the bound parameter is `SqlFloat` or `SqlInteger`, while explicit aliases (`abs(?) as my_abs`) preserve the caller-provided alias name.
- **SQLite JSON operators**: verified that JSON extraction expressions using `->>` (e.g. `'{"a": 42, "b": "text", "c": 3.14}' ->> '$.a'`) properly hydrate integer, string, and float values into `SqlInteger`, `SqlString`, and `SqlFloat`.

Result: passed (all 6 steps verified).
