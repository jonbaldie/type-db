## Journeys exercised

### 1. Coverage-guided float property testing

Goal: generate random 64-bit IEEE 754 doubles (including subnormals, boundary numbers, and extreme exponents) across 50,000 values, roundtripping them through `round_trip_float_string()` and SQLite `REAL` storage.

Result: passed for standard floats, subnormals, and powers of two. (Previously reported issues [#23](https://github.com/jonbaldie/type-db/issues/23) for `-0.0` and [#24](https://github.com/jonbaldie/type-db/issues/24) for stringified `INF`/`-INF` remain open upstream).

### 2. Multi-row and heterogeneous storage class mapping

Goal: evaluate queries returning multiple rows where column values vary in storage class across rows (e.g. `UNION ALL` queries, calculations, and affinity-neutral table columns).

Result: defect found. When an earlier row contains a number (integer or float), `quick_query()` locks the column result kind to that type for the remainder of the query. In subsequent rows, non-numeric strings are unconditionally cast to integer (`0`) or float (`0.0`), corrupting data and making results non-deterministic based on row ordering.

### 3. Mixed parameter placeholder structures and parameter array shapes

Goal: probe parameter placeholder handling across anonymous (`?`), numbered (`?NNN`), and named (`:name`) markers, testing varied ordering of keys in `$sql_values`.

Result: two defects found.
- When named parameters precede positional parameters in `$sql_values`, `sqlite_float_parameter_sql()` misaligns positional placeholder indexing against actual parameter bindings. If the named parameter is a float, the positional `?` gets rewritten to `CAST(? AS REAL)`, corrupting strings to `0.0`. If the named parameter is not a float, an actual float parameter misses the cast and returns as `SqlString`.
- Valid SQLite named parameters starting with digits (e.g. `:1a`) are ignored by `sqlite_float_parameter_sql()` because the identifier regex requires an alphabetic or underscore character after the prefix. Such float parameters miss the `CAST` rewrite and return as `SqlString`.
