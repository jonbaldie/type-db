## Journeys exercised

### 1. Coverage-guided float property testing and SQLite round-trip

Goal: generate 100,000 random 64-bit IEEE-754 doubles across normal numbers, subnormals, powers of two, and boundary values (`PHP_FLOAT_MIN`, `PHP_FLOAT_MAX`, `PHP_FLOAT_EPSILON`, subnormal `5e-324`), roundtripping them through `round_trip_float_string()` and SQLite `REAL` storage.

Result: passed. Every tested double roundtripped bit-identically through PHP formatting and SQLite `CAST(? AS REAL)` evaluation.

### 2. Unicode and non-ASCII named parameter tokenization

Goal: probe SQLite named parameter identifiers containing non-ASCII / multi-byte UTF-8 characters (e.g. `:café`, `:über`, `:π`, `:alpha_β`) across UTF-8 and POSIX/C locales.

Result: defect found ([#38](https://github.com/jonbaldie/type-db/issues/38)).
- `sqlite_float_parameter_sql()` inspects named parameter tokens using `ctype_alnum($sql[$index]) || $sql[$index] === '_'`. In PHP, `ctype_alnum()` fails on UTF-8 continuation bytes (`0x80`..`0xBF`), splitting multi-byte characters mid-token. Under the standard `C` locale (common in CI/container environments), `ctype_alnum()` fails even on leading bytes (`0xC0`..`0xFF`).
- As a consequence:
  1. Floats bound to non-ASCII named parameters (e.g. `:café`, `:π`) miss the `CAST(... AS REAL)` rewrite and return as `SqlString`.
  2. Under the `C` locale, if a query contains `:café` and `$sql_values` contains a float for `:caf`, the tokenizer rewrites `:caf` into `CAST(:caf AS REAL)é`, emitting malformed SQL that fails with a SQLite syntax error.
  3. Under the `C` locale, if a query uses `@über` with an unprefixed key `'über'`, the parameter name fails to match in `$named_parameters`, bypassing the pre-flight `InvalidArgumentException` check and crashing in PDO with an unhandled `PDOException`.

### 3. Dollar-containing named parameter identifiers

Goal: evaluate named parameters containing `$` characters after the leading prefix (e.g. `:a$b`, `:item$price`), which are valid SQLite identifier characters.

Result: defect found ([#39](https://github.com/jonbaldie/type-db/issues/39)).
- `sqlite_float_parameter_sql()` tokenizes identifier characters using only `ctype_alnum($sql[$index]) || $sql[$index] === '_'`. When encountering `$`, it terminates the parameter token at `$`, splitting `:a$b` into `:a` followed by a detached `$b`.
- As a consequence:
  1. Floats bound to `:a$b` miss the `CAST(... AS REAL)` rewrite and return as `SqlString`.
  2. If `$sql_values` contains a value for key `'b'`, the detached `$b` matches `'b'` in `$named_parameters`, throwing a false-positive `InvalidArgumentException: SQLite named parameter "$b" is not supported; use a ":"-prefixed name instead.` despite the query containing the valid colon-prefixed parameter `:a$b`.
