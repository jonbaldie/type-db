# Exploratory testing report: SQLite consumer journeys

Date: 2026-11-08. Tested `origin/main` at `9e0ef9a9ba1f674c4b131cfe061d170d3f336a4d`.

## Environment

The pass used the public PHP API with PHP 8.5.4, PDO SQLite, and SQLite 3.46.1. Composer installed `composer.lock` in a separate worktree with `composer install --no-interaction --no-progress --prefer-dist`. The consumer script created a fresh file database for each run, closed and reopened it, and removed it in a `finally` block. No server, browser, container, image, or volume was started.

The baseline suite ran 333 tests and 1,894 assertions, with 13 skips. PHPStan reported no errors. PHPAssumptions reported zero assumptions in 161 expressions. The [environment and gate output](evidence/2026-11-08/gates.txt) records the commands and results. The skips include external database tests, so the baseline does not establish MySQL or PostgreSQL behavior.

## Journeys

The [consumer script](evidence/2026-11-08/journeys.php) records the calls and literal expected values. The [output](evidence/2026-11-08/journeys.txt) records three runs from fresh databases. All checks passed in each run.

1. **Create and reopen data.** A consumer creates a table and inserts two rows using positional values. The read returns a float stored as SQLite `real` and a null. After reopening the file, a parameterized query returns both rows with their values intact.
2. **Query float parameters.** A repeated named float returns `2.5`, has storage class `real`, and yields `3.5` in an expression. Numbered placeholders return the right values under their original result names. With uppercase column names enabled, an unaliased named float and an aliased float retain the expected names. The mismatched positional-to-named binding in [issue #36](https://github.com/jonbaldie/type-db/issues/36) now throws `InvalidArgumentException`, as documented.
3. **Recover from configuration and write errors.** Under `PDO::NULL_TO_STRING`, a select keeps null distinct from an empty string and leaves the PDO attribute unchanged. Under `PDO::ERRMODE_SILENT`, a duplicate primary key throws `RuntimeException` and leaves two rows. A corrected update remains present after reopening the file.

## Findings and limits

No new confirmed bugs or unresolved candidates were found in these journeys. No issue was filed. The pass checked the existing [binding issue #36](https://github.com/jonbaldie/type-db/issues/36) and its merged [fix #92](https://github.com/jonbaldie/type-db/pull/92). The prior rejection in [issue #23](https://github.com/jonbaldie/type-db/issues/23) explains SQLite's loss of the sign bit for negative zero in real-affinity storage; this pass did not repeat that case. The under-binding behavior recorded in [issue #70](https://github.com/jonbaldie/type-db/issues/70) was not reassessed.

The named-binding error replaces the silent type change described in #36. Consumers must still match the placeholder and value styles documented in the README.

MySQL, MariaDB, PostgreSQL, other PDO drivers, concurrency, transactions, and other PHP versions were not exercised. The local PHP installation has no PostgreSQL PDO driver. No external database server was provisioned. The script samples float and column-name cases; it does not exhaust all SQLite expressions, float values, or PDO settings.

## Replay

Install the lockfile dependencies, then run `php docs/exploratory-testing/evidence/2026-11-08/journeys.php` from the repository root. The script creates and removes scratch SQLite files beside itself. It exits with an exception when a result differs from the expected value.
