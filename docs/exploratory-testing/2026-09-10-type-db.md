# Exploratory testing report: type-db

Date: 2026-09-10

Repository: `main` at `2cbe2f9` (`Fix SQLite numeric parameter storage`)

## Interface and environment

This is a PHP library, so the pass used small consuming programs through the public `TypeDb\Connection`, `quick_query()`, `to_sql()`, and shipped `SqlValue` classes. Each SQLite journey started from a fresh `sqlite::memory:` connection unless noted otherwise.

- PHP 8.4.1
- SQLite 3.43.2 via `pdo_sqlite`
- Composer dependencies installed from the lock file
- Working tree was clean before the pass

## Baseline

All existing quality checks passed before exploratory probing:

- `./vendor/bin/phpunit ./tests --testdox`: 94 tests, 127 assertions passed
- `./vendor/bin/phpstan analyse`: no errors
- `./vendor/bin/phpa ./src`: 0 assumptions in 86 boolean expressions

## Journeys exercised

### 1. Store, retrieve, reopen, and recover

Goal: write ordinary integers, strings, floats, and nulls; read them back as the documented `SqlValue` objects; reopen a file-backed SQLite connection; and continue after a rejected write.

Result: passed. CRUD, a quoted/Unicode/NUL-containing text parameter, persistence after reopening, and a valid insert after a NOT NULL failure all behaved as expected. The retry left exactly the valid row.

### 2. Bind parameters through realistic SQL forms

Goal: use positional, named, numbered, repeated, and SQL-adjacent placeholders without interpreting question marks in literals or comments.

Result: ordinary positional and colon-named parameters passed. Repeated named floats, numbered parameters, question marks inside quoted identifiers/string literals, and question marks inside block/line comments passed. A numbered marker followed by an anonymous marker exposed confirmed issue [#25](https://github.com/jonbaldie/type-db/issues/25): the later `SqlFloat(3.5)` came back as `SqlString('3.5')`.

The SQLite driver itself rejected `@name` and `$name` markers with `column index out of range` even in a direct PDO prepared statement, so that observation was not filed as a TypeDb bug.

### 3. Preserve numeric result fidelity across PDO modes

Goal: round-trip numeric values in REAL and affinity-neutral columns, including special floats, with and without `PDO::ATTR_STRINGIFY_FETCHES`.

Result: ordinary integer/float storage and stringified numeric values in affinity-neutral columns passed. Three confirmed defects were found:

- [#23](https://github.com/jonbaldie/type-db/issues/23): `SqlFloat(-0.0)` returned as positive zero, losing its IEEE-754 sign bit.
- [#24](https://github.com/jonbaldie/type-db/issues/24): stringified `INF` and `-INF` returned as `SqlFloat(0.0)`.
- [#25](https://github.com/jonbaldie/type-db/issues/25): mixed numbered/anonymous placeholder handling returned a float as `SqlString`.

Each confirmed reproducer was replayed three times from a fresh connection with the same result.

## Blocked or unexplored

The MySQL and PostgreSQL PDO extensions are installed, but no local server was available: connections to `127.0.0.1:3306` and `127.0.0.1:5432` were refused. Cross-driver result metadata, binding, and transaction behavior therefore remain unexplored. Transactions, date types, and binary types are also outside the currently implemented roadmap surface.
